# ADR-0017: JSONの重複・型変換・数値精度

状態: ユーザーの修正要求に基づく実装方針（2026-11-10）。APIと数値表現の選択理由を、人間の確認対象として記録する。
重複を上書きしないこと、厳密な型、空の説明・引数名の警告、数値を変える丸めの拒否はユーザー要求である。

## 原因と対象

変更前の`validate_json`と`json.loads`は重複キーを後勝ちで扱う。生成JSONの小数は解析時にfloatへ丸められ、
動的モデルは整数・文字列・boolもfloatへ変換し得る。保存時の`allow_nan=False`だけでは、既に失われた値を復元できない。
対象は両入力、生成JSON、語彙、測定fixture、開発用入力チェック・環境調査で所有するJSON解析箇所。
配布SDKと外部ライブラリ内部の解析は変更しない。

## 解析と検証を分ける

- 標準ライブラリだけの`src/json_io.py`に`loads`を置く。
- `json.loads(object_pairs_hook=...)`が渡す各オブジェクトのペア列から、重複を検出してから辞書を作る。
  入れ子とエスケープ後に同名となるキーも対象。同名でも異なるオブジェクトなら許す。
- `parse_constant`でNaN・Infinityを拒否し、`parse_float=Decimal`で小数の値を丸めず受け取る。整数は標準のint。
- 解析後、`TypeAdapter.validate_python(..., strict=True)`またはstrictなPydanticモデルで形・型を検証する。
  定義の名前・フィールド・対応型はPydanticに、集合の空・名前重複は既存のindex処理に集める。
- 深さや数値の解釈が標準パーサーの技術的限界を超える場合も、文脈付きの既存エラーへ変換する。

`TypeAdapter.validate_json`自体を否定する変更ではない。現行APIには重複拒否の設定がないため、
重複検査後にもう一度解析する方式より、1回解析してPydanticへ渡す方針とする。
再解析による小数の丸めを避け、検査の責務を1箇所にまとめるためであり、高速化を理由とはしない。
独自のJSON字句解析器は作らない。標準フックのペア列の分、一時的なメモリと検査処理は増える。

## 型と警告

`ParamSpec`・`FunctionDef`・`FunctionCall`と動的引数モデルはstrictにし、余分なキーも拒否する。
numberはintとfloatの両方を許し、bool・文字列・全角数字をnumberへ変換しない。
booleanへの整数・文字列の変換も許さない。数値表現を含む自然言語の意味解釈とは別の契約である。

FunctionDefのPydantic検証で関数名の空・空白を拒否し、入力をstripして保存し直さない。
空のdescriptionと空・空白の引数名は、モデル検証後に標準loggingで警告し、そのまま受理する。
関数名と引数の位置・名前をrepr付きで通知する。通常の起動ではTUIの開始前にstderrへ出る。
引数が0個の関数も受け付ける。警告は最終JSONへ入れない。

## 数値の表現と保持条件

1. JSON整数はintのまま保持する。`9007199254740993`や数百桁の整数もfloatへ変換しない。
2. 小数・指数表記はまずDecimalで正確に読む。有限のfloat候補を作り、その標準JSON表記をDecimalへ戻す。
   元の値と数学的に等しい場合だけfloatを採用する。`0.1`はこの条件を満たす。
3. floatのJSON表記で値が変わるが、元のDecimalが整数値で、floatの有限範囲内ならintへ戻して保持する。
   例: `9007199254740993.0`は`9007199254740993`として保持できる。
4. それ以外の精度損失・アンダーフロー・オーバーフロー・非有限値は、理由付きの検証エラーにする。
   桁数の多い小数を黙って短くせず、文字列に変えてnumber型を壊すこともしない。
5. 最終値はint/float/str/boolのスカラーとし、標準`json.dump(..., allow_nan=False)`で数値として保存する。

内部floatが二進数で厳密な0.1であることは求めない。最終JSONを十進数として読んだ値が元と一致することを検査する。
Decimalのまま保存する案は、Pydantic標準のJSON出力で文字列になり、標準jsonもDecimalを数値として書けない。
今回の最小案では独自の数値エンコーダーを加えず、保持できない小数を明確に拒否する。

数値の制限はPythonのint文字列変換の実行時上限、floatの有限範囲とJSON再出力で保持できる精度、
既存の生成上限256トークンに基づく。新たな桁数定数は置かない。
整数JSONなら保持できる巨大値でも、小数・指数表記ではfloat候補の範囲外として拒否する場合がある。
他のシステムが出力JSONをfloatだけで読む場合の丸めは、そのシステム側の制約である。

## 既存処理と検証

読み込みの失敗はStartupError、生成後の検証失敗はPromptErrorにし、前者は起動終了、後者は件を飛ばして継続する。
原子的保存、TUI、名前辞書と制約付き生成は維持する。測定の期待値も十進値と型を区別して比較する。
ADR-0004の一律float化・暗黙変換許可は置き換える。ADR-0015の改行・桁区切りは実装せず、
将来の正規化にも今回の数値保持条件を適用する設計へ修正する。

重複・非標準JSON、strict型、警告、整数境界、長い小数、非有限値、保存後の十進値一致を先にテストする。
実装後に全テスト・lint・独立レビューを行い、解析の時間測定とモデル精度測定を混ぜない。
API比較では100小数引数の検査は中央値0.1789msで、重複検査なしの0.0253msより増えた。
条件・全試行と限界は[検証記録](../../implementation-verification.md)を参照する。

## 見直す条件

長い小数を正確に出す必要が評価データで明らかになった場合は、DecimalをJSON数値として
安全に出せる成熟した出力APIと、その依存・保守費用を比較する。独自エンコーダーは今回は採らない。
小数検査や語彙解析の時間・メモリが全体の制約になる場合は、同じ拒否条件を保ったまま実測して見直す。
LF方式は別の生成設計として承認・検証し、今回の検証変更から実装済みとは判断しない。
