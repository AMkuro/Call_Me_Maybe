# ADR-0003: 文字列の値

状態: **保留**(ユーザー、2026-11-08)。実装ができてから、追加が必要かどうかを考える。

## 背景
PoC で次の3種類の失敗を観察した。ただし、実験の条件は揃っておらず、頻度は分からない。設計の根拠にはせず、仮説としてテストに入れる。

- 引用符: 値の中の二重引用符が、単一引用符に変わった(`the "best" day`)。
- 先頭の空白: 値が空白付きのトークンで始まった(置換文字列 ` *`)。
- 正規表現: `digit` や `aeiou` など、正規表現として不適切な値(例を増やすと直った)。

## 現時点の方針
- 【設計判断】値の文字列は、JSON の文字列として有効なトークンだけを許す。
- 【設計判断】値のトークン数に上限を設ける(引用符を閉じ忘れて、呼び出しが続くのを防ぐ)。上限の値は未定。
- 上記以外(先頭空白の扱い、引用符の扱い、入力の部分文字列への制約)は、**決めない**。

## 論点(実装後に判断する)
- 値に `"` が含まれる場合だけ、JSON の `\"` が必要になる。サンプルのプロンプトでは、引用符は区切りで、
  値には入らない。頻度は低いと推測する(未測定)。
- 案i: モデルに `\"` を出させる。案ii: 素の文字列を作らせ、エスケープはコードが行う。
  案iiは、JSON の構造の制約から外れるため、Subject への防御が弱くなる。
- 先頭の空白を禁止する規則は、正当な値(`" "`)を壊す。
- 入力の部分文字列に制約する案は、正規表現のように入力に無い値に使えない。

## 見直しの条件
- 失敗解析で、文字列の値が原因の誤りが目立ったとき。
