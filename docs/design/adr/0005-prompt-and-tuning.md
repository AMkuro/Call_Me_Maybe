# ADR-0005: プロンプトと調整

状態: 決定(ユーザー、2026-11-08)。

## 背景
- 【測定】入力が長いほど、1回あたりの呼び出しが重くなる(KV キャッシュなし)。README の CPU 測定
  (dev 30件): 入力236トークンで340秒、553トークンで704秒。
- 段1は全関数の説明を入れるので、関数が増えるとプロンプトが長くなる。レビューでは関数セットが変わる。
- 前回の PoC は、条件が揃っておらず、プロンプトの比較には使えない。

## 決定
- 【設計判断】プロンプトは設定として差し替えられる部品にする(ファイルまたは設定値)。
- 【設計判断】最初は最小の構成(例なし)にする。例の数や長さは、測定し直して決める。
- 【設計判断】調整は、精度の向上と時間の調整を、測定のループで繰り返す。ループの実行は、Claude Code などに
  任せてよい。
- 【設計判断】テストケースは、データ形式(JSON など)にして、置くだけで評価が回る形にする。テストの作成は
  ユーザーが ChatGPT などで行う。
- 【設計判断】段2のプロンプトには、選ばれた1関数の説明だけを入れる。

## 見直しの条件
- 精度または時間が目標を満たさないとき。

## 2026-11-11: テストの作成者（ユーザー決定）
- テストは Claude Code が作ってもよい。ただし調整に使う評価集合は、調整を行うセッションから隔離して作る。
  別のサブエージェントに型の一覧だけを渡して作らせ、調整側のセッションは中身を読まず、点数だけを受け取る。
- 作った集合はユーザーが確認する。最初の対象は ADR-0020 の新しい正規表現の集合。
