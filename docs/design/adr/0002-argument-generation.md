# ADR-0002: 引数の作り方

状態: 決定(ユーザー、2026-11-08)。

## 背景
- 【明文】出力の各オブジェクトのキーは、ちょうど `prompt`、`name`、`parameters`(V.4)。
- 【明文】JSON の構文だけでなくスキーマも強制する。プロンプトだけに頼ってはならない(V.3.3)。
- 【測定】KV キャッシュが無いので、logits を呼ぶ回数と入力長が時間を決める(ADR-0001)。

## 選択肢
- a. 骨組みを強制する: 関数定義から、`{"name": "…", "parameters": {"a": ` などの構造を組み立てて強制し、
  値の部分だけをモデルに生成させる。
- b. JSON 全体を文法で縛り、キーまでモデルに選ばせる。

## 決定
**a**。

- 【設計判断】`prompt` は入力からそのままコピーする。モデルには生成させない。
- 【設計判断】キーの順序は関数定義の順序にする。
- 【設計判断】強制した骨組みのトークンは入力列に足すが、logits は呼ばない。
- 【設計判断】生成した全文を JSON としてパースし、関数定義から動的に作る pydantic のモデルで検証する
  (数値の扱いは ADR-0004)。
- 【解釈】骨組みの強制は、候補が1つの位置の制約付きデコードと同じ扱いにできる(ADR-0001 の論理)。

## 未決の細部
- 空白の入れ方(`": "` と `":"`)。トークンの切れ方が変わる。段2のプロンプトが指示する形式と、強制する骨組みの
  形式を揃える。設計文書の次の版で決める。

## 見直しの条件
- 骨組みの強制がモデルの出力を乱して、精度が下がる場合(例: 形式がプロンプトの指示と食い違う)。
