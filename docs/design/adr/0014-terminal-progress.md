# ADR-0014: 選択と生成を追う端末表示

状態: **TUI の追加・トークン単位の表示はユーザー承認済み**(2026-11-10)。
以下の配置や端末処理の細部はエージェントが選んだ実装詳細。

## 背景と要求

ユーザーは、プロンプトを調整する際に数値付き警告だけでなく、何が選ばれているかを
TUI で確認したいと指示した。Subject v1.7 第8章の生成過程の可視化に対応する。
推論の結果を観察するための表示とし、表示によって選択や生成結果を変えない。

## 選択肢とトレードオフ

- 通常ログだけ: 保存や比較は容易だが、生成途中を追うと画面が流れる。
- 端末上で同じ領域を更新: 入力、選択した関数、生成中の値、診断値を一度に見られる。
- curses や外部 TUI ライブラリ: 操作画面を作れるが、今回は対話操作の要求がなく依存も増える。

## 実装案

標準ライブラリと ANSI 制御で端末上の表示を更新する。stderr が端末のときに自動表示し、
リダイレクト時は制御文字を出さず、選択結果と警告の通常ログにする。stdout は結果表示に使わない。
追加の推論やキー入力待ちは設けない。終了・例外・中断時にカーソル等の端末状態を戻す。

表示項目:

- 入力番号 / 総数と元の指示、現在の段階。
- 名前の生成中の接頭辞と、確定した関数名。
- 現在の引数名・型と、生成済みの値、採用トークン。
- 名前の分岐では、制約前の第1候補、採用候補、許可確率の合計、上位2候補の logit 差。
- 1候補だけの位置は「強制」と表示し、未計算の確率を0や100%として表示しない。
- 警告と最後の成功 / エラー。制御文字を含む入力は表示用にエスケープする。

decoder は選択ごとに任意の通知関数へデータを渡し、pipeline が名前・引数の文脈を付ける。
main が入力番号と端末表示を担当する。通知を指定しなければ計算結果は同じ。
これは実行時の観察要件に必要な通知であり、モデルを差し替えるテスト用インターフェースではない。

## 検証と見直し

純粋な整形と数値は固定データで検証する。疑似端末で実プロセスの表示と端末復帰を確認し、
リダイレクト時に制御文字が出ないこと、表示の有無で同じ出力になることを確認する。
大きな入力で画面を占有しすぎる場合は、表示幅と末尾表示を調整する。
