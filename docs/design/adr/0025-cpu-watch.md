# ADR-0025: CPU 実行の見張り（cpu-watch）

状態: 決定（ユーザー、2026-11-11）。下の「提案」の節も同日に承認された。

## develop統合時の位置付け（2026-11-12）

feat/cpu-watchの83c54afから、独立したCPU監視ツールとテストを部分採用した。
番号重複を避け0021から0025へ改番する。以下のユーザー決定と測定は当時の履歴として残す。
CPUでの精度探索を通常運用にする指示と作業ブランチの指定は、現在のGPU開発・develop集約方針により失効した。
ツールは明示的なCPU測定・調査用にだけ残し、アプリやGPU実行から自動起動しない。
停止して調査するthermalモード（ADR-0022）とは別の、任意ジョブを一時停止する道具である。
実機温度センサーを使った試験と、sandbox内外の時間一致は今回確認していない。

## 背景

- 【測定】2026-11-10 11:49〜12:14 JST、実モデルを CPU で約 6 本並列（各 4 スレッド）に動かし、
  CPU パッケージ温度（k10temp の Tctl）が 98 ℃ 以上に 1500 秒中 1437 秒張り付いた（最高 99.6 ℃、Netdata）。
  100 ℃（Tjmax）には届かないので、「100 ℃ で止める」では止まらない。
- 【測定】同日 12:14 台に負荷が消えると、Tctl は 10 秒で 91 ℃ から 53 ℃ に下がった（Netdata、10 秒ごと）。
- `research/evo-x3/measure.sh`（ADR-0010）は開始前の冷却待ちと最高温度の記録だけで、実行中に止めない。
- 【測定】Claude Code の sandbox の中では `systemd-run --user` が動かない（`Failed to connect to bus`）。
  `taskset` は動く（`taskset -c 0-15 nproc` が 16）。プロセスグループへの `SIGSTOP`/`SIGCONT` も効く。
  sandbox の中には `uv` が無い。
- 【測定】過去の時間測定の最大 RSS は約 4.7 GiB（t5・t6・t8）で、`MemoryMax=16G` は効いていない。
  スワップは有効（8 GiB）。

## 決定

### ユーザー決定（2026-11-11）

- 精度の評価（プロンプトの調整）は CPU で、**2 本並列 × 各 8 スレッド**で始める。
- 熱いときは止めずに**一時停止**し、冷めたら再開する（条件待ち）。途中の計算を捨てない。
- 置き場所は `origin/develop` ではなく `feat/implementation` から切った `feat/cpu-watch`。
  理由: 冷却待ちを入れた `measure.sh` と ADR-0010 の 11-11 の追記が、まだ develop に無い。
- 時間の測定も sandbox の中に移す。ただし、`measure.sh`（sandbox の外、承認つき）と 1 回比べて
  一致を確かめてから。一致したら ADR-0010 を更新する。

### 提案（2026-11-11 承認）

- 実装は Python の標準ライブラリだけで `tools/cpu_watch.py` に書く。
  理由: 窓の判定と一時停止の状態遷移を純関数にして、データで直接テストできる（AGENTS.md の方針）。
  bash の `measure.sh` は置き換えない。
- 使い方: `.venv/bin/python -m tools.cpu_watch <ジョブ一覧.json> <ラベル>`。
  一覧は「引数の配列」の配列で、シェルを通さずに起動する。同時に動かすのは 2 本まで。
- 全ジョブを `taskset -c 0-15` に固定し、`OMP_NUM_THREADS=8` を渡す。合計 16 で、CPU を固定する範囲と同じ。
- 開始前の冷却待ちは `measure.sh` と同じ（Tctl 50 ℃ 以下まで待つ。60 秒で 1 ℃ も下がらなければ始めない）。
- 1 秒ごとに Tctl と MemAvailable を読む。時間は単調時計（`time.monotonic`）で数える。
- **一時停止:** Tctl 95 ℃ 以上が直近 120 秒のうち 60 秒以上になったら、全ジョブのプロセスグループに `SIGSTOP`。
  - 再開: Tctl 70 ℃ 以下で `SIGCONT`。窓は空にして数え直す。
  - 一時停止中に 60 秒間 1 ℃ も下がらなければ、全ジョブを止める（`SIGTERM`、10 秒後に `SIGKILL`）。
- **止める:** MemAvailable が 8 GiB 未満の状態が 10 秒続いたとき。センサーやメモリ情報が読めないとき。
  見張り自身が `SIGINT`/`SIGTERM` を受けたとき。
- 時間の上限は置かない。
- 記録: `research/evo-x3/watch/<ラベル>/` に、1 秒ごとの値（時刻・Tctl・MemAvailable・一時停止中か）、
  ジョブごとの標準出力・エラーと終了コード、一時停止の回数と合計秒数。
  一時停止した実行は、時間の測定としては熱の影響を受けたものとして区別する（ADR-0010）。
- 数値（95 ℃・60/120 秒・70 ℃・8 GiB）は、上の測定から選んだ初期値。

## 検証

- 窓の判定・一時停止の状態遷移・冷却待ち・値の検査は、温度と時刻の列を与えてテストする。
- プロセスの操作は、短い本物のジョブ（`sleep` など）と、偽の温度を書いたファイルでテストする。
- 実機: 2 本 × 8 スレッドで実際に動かし、Tctl の推移を記録する。わざと高温にはしない。

## 見直しの条件

- 2 本 × 8 スレッドで一時停止が頻繁に起きるとき（並列数か閾値を見直す）。
- 一時停止しても 60 秒以内に 70 ℃ まで下がらない事例が出たとき。
- 時間の測定の比較で、sandbox の中と外の結果が一致しなかったとき（時間の測定は外に残す）。
