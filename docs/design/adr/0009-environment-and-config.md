# ADR-0009: 環境と設定

状態: 決定(ユーザー、2026-11-08)。未確定の細部あり。

## 背景
- 開発環境とレビュー環境は違う。モデルの保存場所は、開発機もレビュー機も `~/goinfre` か `~/sgoinfre`
  (容量のため、そこを使うしかない)。
- 旧環境は別の場所へ移動した。今回はその中身を使わず、クリーンに作り直す。
- 【明文】時間の評価の基準は CPU。GPU は、プロンプトの精度を上げるときに後で使う。

## 決定
- 【設計判断】仮想環境は、既定でリポジトリ内の `.venv`(`uv sync`)。置き場所は、パラメータで指定できるようにする。
- 【設計判断】設定は `.local.mk` のような名前のファイルに置き、Make から読み込む。`.env` の名前は使わない
  (理由は、エージェント側の権限設定で `.env` 系の読み取りを禁止しているため。プロジェクトの要件ではない)。
  このファイルは Git 管理外とする。
- 【設計判断】モデルの保存場所は、環境変数を見て探しに行く。探す順序の案: 明示の指定 → `~/sgoinfre` →
  `~/goinfre` → Hugging Face の既定。
- 【設計判断】時間の評価は CPU で行う。GPU は後で、既存の SDK 環境に `accelerate` を足して使う。
  SDK 自体は変えない。

## 未確定
- 設定ファイルの扱いと CI の関係: 「コードか Make の中に書き、CI では開発環境のままであることを伝える」
  のか、「パスを同じにして揃える」のか。
- レビュー機で見る環境変数の正確な名前と、ディレクトリの構成。実機で調べる(ユーザー、2026-11-08)。
- ロックファイル(ADR-0007)の名前と置き場。実装時に適当に決め、気に入らなければ直す。重要度は低い。
- 時間の評価の測定プロファイル(CPU の固定、スレッド数)は、`research/evo-x3/README.md` の `phys16-t8` が
  基準。クリーンな環境でも同じ前提で測るか。

## 見直しの条件
- レビュー機のモデル保存場所が、想定と違うと分かったとき。
