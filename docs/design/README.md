# 設計記録(docs/design)

状態: **スケルトン承認済み**(2026-11-10、PR #43)。ユーザーから本実装への着手指示を受けた。
ADR-0013 の詳細をユーザーが承認した。トークン単位の TUI 表示は ADR-0014 に記録した。

要求・要件から処理への対応、データの受け渡し、失敗時の動作、部品の変更条件は
[基盤実装の設計](../architecture.md) にある。最初にこの設計を読み、判断の理由は下の ADR を参照する。

記号は `docs/subject-v1.7.md` と同じ。

- 【明文】Subject に書かれている事項
- 【解釈】明文から導いた読み。Subject は明言していない
- 【設計判断】このプロジェクトが決めたこと。Subject の要求ではない
- 【測定】実測または実ファイルで確かめた事実(条件つき)

## 未解決の一覧
1. 関数が増えたときの関数選択の精度(ADR-0001)。関数セットを変えたテストで測る。
2. 文字列の値の細部(ADR-0003)。実装後に、必要になったら決める。
3. (解決済み、2026-11-09)モデルのファイルの確認は取りやめた。例外処理だけにする(ADR-0007 の更新)。
4. (解決済み、2026-11-09)配布 SDK を lint の対象から外すことは、ユーザーが認めた(ADR-0008)。
   レビュアーが同意するかは確かめられない。
5. 設定ファイルの扱いと CI の関係(ADR-0009)。
6. レビュー機のモデル保存場所の正確な探し方(ADR-0009)。実機で調べる。
7. Subject が未定義の点: 5分の範囲、「全テストプロンプト」の件数、出力パス、整数相当値の表記
   (`docs/subject-v1.7.md` の第9章)。
8. (解決済み、2026-11-09)`pyproject.toml` の構成は確定した(ADR-0008、0009 の「2026-11-09 の更新」)。
   残りは、手元の Mac が Intel の場合の torch の制約。(提出前に `llm_sdk/` を戻す確認は、仕組みにしない。)
9. (暫定解決、2026-11-10)名前の終端は EOS を採用(ADR-0013)。障害となれば見直す。
