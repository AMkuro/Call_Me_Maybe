## 結果の一致と機能検証（精度測定とは別）

固定logitsと実際の制約処理を使い、表示なし・リダイレクト・利用不可・書込み失敗で、
検証後の結果と全forward入力が一致することを確認した。
引数なし関数でも固定トークンの通知数と本文が一致する。
number・string・booleanを含む独立に用意した期待本文に対して、語彙バイトの累積が一致し、
整数の生成列には`.0`がなく、保存本文にだけ`.0`があることも検証した。

実モデルはホストでGPUが利用可能なことを確認してから、`.venv-gpu`と`make gpu-run`で実行した。
GPUはRadeon 8060S Graphics。既存のofflineモデルキャッシュを使用した。
標準入力の1件目の数値と5件目の文字列を、80列24行の擬似端末とstderrリダイレクトでそれぞれ処理した。
どちらも2件成功、終了コード0で、保存ファイルはバイト単位で一致した。
これは2入力の回帰確認であり、未見入力の正答率を測定したものではない。
[TTY出力JSON](../measurements/2026-11-19-json-preview/tty-output.json)と
[リダイレクト出力JSON](../measurements/2026-11-19-json-preview/redirected-output.json)を保持する。
GPUでprogress=Noneにした比較は行っておらず、その条件は固定logitsで確認した。

既存の擬似端末テストではRuntimeError・Ctrl+C後のカーソルとalternate screenの復帰を確認する。
非TTYの警告・各入力の結果・全体要約は従来どおりで、JSON本文やANSIは追加しない。
stdoutとJSON保存先の契約は変えない。
独立レビューで見つかった関数名・引数名の制御文字、小画面のエラー優先順位、終了後の幅固定は、
再現するテストを先に追加して修正した。再レビューでは追加の指摘はなかった。

## 表示性能（推論・正答率の測定とは別）

500 ASCIIトークンの接頭辞を繰り返す、モデルなしの短時間試験を行った。
フレーム間隔の時計を固定／2msずつ／100msずつ進め、実測にはperf_counterを使った。
各条件を単独で3回実行し、外れ値は除外していない。SDK呼出しやhardware probeはない。

| 条件 | 1試行の通知数 | 通知あたり実測中央値 |
| --- | ---: | ---: |
| リダイレクト（描画なし） | 50,000 | 1.28 µs |
| TTY・再描画を抑止 | 50,000 | 7.19 µs |
| TTY・500トークン/秒を模擬、50ms間隔で描画 | 50,000 | 17.54 µs |
| TTY・毎トークン描画 | 5,000 | 277.78 µs |

毎トークン描画の試行全体は1.350、1.405、1.389秒だった。
この条件で500トークンなら表示処理約0.14秒に相当するが、実アプリ全体の測定ではない。
StringIOへの書込みとmock時計の費用を含み、端末エミュレータ自体の処理は含まない。
長い接頭辞・端末・機材で費用は変わる。今回の試験から表示処理が数分を消費する兆候はないが、
Subjectの標準ハードウェアでの5分制限を認定するものではない。
実モデルのTTY/リダイレクト実行は機能確認のためで、2回の時間差を表示オーバーヘッドとして扱わない。

[生データ](../measurements/2026-11-19-json-preview/display-timing.json)と
[再現用の試験コード](../measurements/2026-11-19-json-preview/benchmark.py.txt)を保持する。
試験コードはリポジトリルートから`PYTHONPATH="$PWD" .venv/bin/python <保存した.py>`で動かす。
この表示試験にキャンパス推定の+8秒は適用しない。

## 実際の画面

GPUの擬似端末実行で取得した生成途中のフレーム。`a`は整数として生成された実際の内容で、
保存用の`.0`はまだ表示していない。`b`のスロットが最後の内側の`}`まで確定し、外側の`}`は未生成である。

```text
Call Me Maybe    1/2
Stage: generate_call_json
Function: fn_add_numbers
Parameter: b (number)
Elapsed: 24.6 s  Tokens: 35
Token: 92 (greedy)
───────────────────────────────────────────────────────────────────────────────
JSON OUTPUT — committed prefix
{
  "prompt":"What is the sum of 2 and 3?",
  "name":"fn_add_numbers",
  "parameters":{
    "a": 2,
    "b": 3
  }▌
```

[全TTY記録](../measurements/2026-11-19-json-preview/gpu-tty.json)はANSIをJSONエスケープして保存した。
この記録は最初の実モデル確認時の画面であり、その後、制御文字の処理・小画面の優先順位・終了後の幅を修正した。
完了時の見出しは`SAVED JSON — validated`となり、検証済みの保存本文を表示する。
終了後は各件の結果・時間、出力先、全体の件数・時間だけを残す。
ユーザーの追加指示（2026-11-19）により、終了後のプレビュー再表示は削除した。
失敗・中断の理由は残すが、JSON本文や名前選択の途中状態は再表示しない。
全成功JSONは出力ファイルで確認できる。

## チェックと制約

`make install`は成功。sandboxではuvのキャッシュが読取専用だったため、通常のホスト環境で実行した。
`make lint`はflake8とSubject指定のmypyが成功（57ソースファイル）。
`make test`は278テストが成功した。`git diff --check`も成功した。

画面に収まらないJSONは先頭を省略して末尾を表示する。スクロール操作や全件のJSON履歴は追加していない。
全幅文字と結合文字を考慮するが、絵文字の複合書記素の幅は端末によって異なる。
表示は同期通知時に更新するため、1回のforwardが長い間は経過時間も更新しない。
実行中のJSONプレビューは維持し、終了後のJSON確認には保存ファイルを使う。
成功・失敗・例外・Ctrl+C後に本文が残らないことと、結果・時間・保存先が残ることを回帰テストで確認する。
全件の再精度測定、キャンパスCPUでの実アプリ時間測定は今回行っていない。
