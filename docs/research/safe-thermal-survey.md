# 校舎CPUを連続負荷で測る

`tools.campus_survey thermal`は、同じSDK入力を繰り返し、自らの負荷で温まる過程を測る。
モデルを一度ロードし、16・64・256トークンを順番に連続処理する。
初回forwardを分け、その後の処理時間と温度時系列を入力長ごとに残す。
手動で通常温度と高温を作り分ける必要はない。
これはSDK負荷の診断であり、実アプリやSubjectの全テスト5分未満の判定を代替しない。

## 校舎での実行

既存のCPU用SDK環境とモデルキャッシュを使い、リポジトリ直下から実行する。
`--hf-home`は既存のHugging Faceホームで、通常はその下に`hub/`がある。
モデル取得・自動インストールはしない。出力名は毎回変える。

```sh
.venv/bin/python -m tools.campus_survey thermal \
  --pc-id cmm-007 --hf-home "$HOME/goinfre/huggingface" \
  --output /tmp/campus-thermal-001.jsonl
```

校舎には開発機用のCPU固定・容量制限を付けない。
スレッド数は既定で継承する。明示して比較する場合だけ`--threads 8`等を付ける。
負荷期間はモデルロード・初回処理の後に300秒、子の起動以降の全体予算は360秒。
安全停止条件へ達したら即座に中止し、自動再開しない。

## 安全停止

- CPU温度が85℃、または取得できたCPU固有のcrit値の10℃手前の、低い方へ到達。
- core/package thermal counterが開始時より増加、または減少して比較不能。
- 温度・thermal counter・必須メモリ情報が欠測、不正、読み取り不能。
- ホストと取得可能なcgroupの残メモリの小さい方が1024MiB未満。
- 時間切れ、Ctrl-C/SIGTERM、子プロセスの失敗、記録の書き込み失敗。

親が0.5秒間隔で監視し、停止時は対象プロセス群へSIGTERM、1秒後も残る群へSIGKILLを送る。
85℃は測定器の既定上限で、全CPUの保証温度ではない。
`--max-temp-c`は1〜95℃、`--min-free-mib`は512MiB以上を指定できるが、crit値の10℃手前の制限は維持する。
監視を無効にするオプションはない。サンプリングによる対策であり、急変や物理故障を防ぐ保証ではない。

Intelのthermal counterが見えないAMDやVMゲストでは、負荷開始前に停止する。
電力・CPU割当による速度低下は熱スロットリングとは別に記録する。周波数低下だけで熱が原因と断定しない。

## 記録の読み方

権限600の新規ファイルへJSON Linesを逐次flushする。既存ファイル・symlinkへ上書きしない。
各行は独立したJSONで、最後の`summary`がなければ未完了である。

| event | 内容 |
| --- | --- |
| metadata | 匿名ID、UTC、commit、SDK/lock/調査器のハッシュ、環境、CPUコア・SMT対応 |
| sample | 経過時間、センサー別の温度、thermal counter、残メモリ、周波数、RAPL、CPU割当待機 |
| stage | モデルロード、連続処理などの段階 |
| warmup | 各入力長の初回forward。集計には混ぜない |
| forward | 入力トークン数、開始からの経過ナノ秒、処理ナノ秒 |
| summary | 終了理由、入力長別の回数・中央値・最初/最後の5回の中央値の比 |

`late_early_ratio=1.2`なら、同じ入力長の最後の5回の中央値が最初の5回より20%長い。
10回未満では比を出さない。外れ値を削除せず、温度との相関だけで因果を決めない。
周波数は`scaling_cur_freq`の値で、実効クロックとは限らない。
RAPLはマイクロジュール単位の累積電力量と最大範囲を残す。電力を求める場合は時刻差とカウンターの周回を考慮する。
任意情報は欠測理由を残すが、必須の監視情報がなければ継続しない。

終了コードは0=期間完了、1=測定/書込失敗、2=引数不正、3=起動前の条件不足、4=安全停止/予算超過、
130=Ctrl-C、143=SIGTERM。0でもSubjectの時間要件を満たした証明にはならない。

## VMとcgroup

VMはOS分離に加え、CPU・メモリ・swap・依存をまとめて管理できる点でも候補とする。
同じOS・Python・依存をゲストへ固定し、vCPUの配置・メモリ・swapをそろえ、負荷ごとに校舎と比較する。
物理温度の監視はホスト側が必要で、ゲストにセンサーがない場合に本ツールの停止条件を迂回しない。
ホストの監視とゲストの負荷を連携するVM制御は、今回の版に含めていない。

2026-11-11の開発ホストでは、sandbox外で/dev/kvmの存在を確認したが、現在のユーザーは読み書き不可だった。
qemu-system-x86_64、virsh、virt-installは未導入。VMの作成・起動、権限の準備は未実施。
AMDのk10tempは読めるがthermal counterはないため、本ツールはモデルを起動しない。
これを「VMが使えない」「AMDに熱制限がない」という判断には置き換えない。

目的と計算値は[元の診断](campus-runtime-feasibility.md)、停止・保存の契約は
[実装設計](../superpowers/specs/2026-11-11-safe-thermal-survey.md)、判断は
[ADR-0022](../design/adr/0022-campus-runtime-calibration.md)を参照する。
