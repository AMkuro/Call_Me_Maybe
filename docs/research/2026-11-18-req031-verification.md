## コードレビュー

`values.py`の完成文法は`-?(?:0|[1-9][0-9]*)\.[0-9]+`に一致する。
`_NUMBER_PREFIX`が整数だけを許すのは、その後に小数点を生成できる接頭辞だからであり、整数での終端許可ではない。
小数部分まで完成しなければ`,`／`}`を採用できず、空白を挟んで未完成数値を終端することもできない。
候補判定・終了判定は同じ`_value_state`を使用し、複数文字トークンも追加バイト全体を検査する。

`generate_value`のP + O + V、一意候補の推論省略、256トークン上限、名前選択・EOSは変更されていない。
小数点と小数部は実際の値ループの選択IDに含まれる。プログラムが`.0`を補う処理はない。
固定JSONの`<` escapeと、SDK復号・語彙bytes・期待断片の照合も維持されている。

`json_io.loads`は重複キーと非有限値を拒否し、小数をDecimalで解析する。
`validate_call`はstrictなFunctionCall、選択名、関数定義から作る引数モデルで検証する。
汎用検証や入力解析は整数・指数も扱い得るが、LLMの生成文法とは別の契約である。
そのため既存の整数入力・指数解析テストを小数専用へ書き換える必要はなかった。

### PrivateAttrと保存の信頼境界

`process_prompt`は全文検証と入力prompt一致の確認後に限り、本文を`_generated_json`へ設定する。
`__main__._process_all`は返ったcallを変更せず直ちに保存し、後の累積保存でも変更しない。
writerは本文を再検証せず信用するが、現行の入口はこの検証済み経路だけである。
JSON入力からprivate属性を設定することはextra禁止により拒否され、公開`model_dump`／JSON schemaにも出ない。

この属性自体は検証済みであることを型で保証する仕組みではない。
private属性の意図的変更や、浅いfrozenモデル内のparameters辞書を書き換える新しい呼出元には、本文との一致を保証する責任がある。
そのような経路は現在ないため、writerの全面再解析や新クラスは追加しなかった。
未使用のmodel_copyやprivate属性の改ざんだけを理由に、通常の生成・保存を不具合とは判定していない。

生成済み本文は再シリアライズされず、内部がintへ正規化された数値も元の小数表記のまま保存される。
直接構築されprivate属性がないFunctionCallは、ADR-0017に記載された従来のJSONシリアライズへ進む。
JSON文字列内の`1e10`等を数値として置換する処理はない。
同一ディレクトリの一時ファイルへ書いてclose後に`os.replace`し、失敗時は一時ファイルを削除する。
原子的更新、既存ファイル保持、失敗後継続と成功順序の契約は維持されている。

独立した別エージェントのレビューも、現行呼出経路のコード不具合は指摘しなかった。

| 対象 | 確認内容 |
| --- | --- |
| 正常9数値、両区切り | 指定された0.0〜巨大整数部・2.00まで、各バイトの合法接頭辞を経由して完成できる |
| 異常12数値、両区切り | 整数終端、空小数、先頭ゼロ、プラス、指数、非有限、区切り後の余分な文章を候補から拒否 |
| 複数文字トークン | `2.0`、`2.0,`、`.0}`を文脈に応じて許可し、`1e10`、`1.0e10`、`0,`を拒否 |
| 小数部の選択 | 一意候補で確定した`2.`の後、実際のマスクでモデルが`5}`を選び`2.5}`になる。次forward入力にprefix全履歴がある。encode呼出しなし |
| 上限 | 実number文法で256トークン目の完成は成功、257なら上限失敗 |
| 累積保存 | 正常9値を1件ずつ累積保存し、parse_floatで観測したリテラルが入力文字列と完全一致。Decimalの符号・指数・桁列も一致 |
| 精度拒否 | 過剰精度小数、非ゼロのアンダーフロー、float範囲外の小数を既存の理由で拒否 |
| 信頼済み本文への入口 | bool・数値文字列・NaN・重複キーはprocess_promptから返らず、入力によるprivate属性設定も拒否 |
| 属性なし・空配列 | 手動callの従来保存と`[]`を確認 |
| 保存失敗 | 生成済み本文の書込み中と置換時のOSErrorで、既存ファイルと一時ファイル清掃を確認 |
| 途中失敗 | 実際の処理ループ・writerで成功順序を保ち、全件失敗では空配列へ更新 |

数値と混在する日本語、引用符、バックスラッシュ、改行、特殊表記、数値に似たstring、booleanも検査した。
