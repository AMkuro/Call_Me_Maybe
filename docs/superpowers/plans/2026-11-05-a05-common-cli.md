# A05 Common CLI Implementation Plan

> Execute inline with superpowers:executing-plans. The user authorized routine
> design decisions, implementation, tests, and self-review without approval gates.

**Goal:** Implement the shared CLI, validation, and incremental saving in #25.
**Architecture:** A callable processes one prompt with dynamic definitions and
returns JSON text. Pydantic validates the input and final output; the CLI owns
the sequential loop and atomic replacement of the cumulative JSON array.
**Tech Stack:** Python >=3.10, standard library, Pydantic v2, uv, unittest.
**Spec:** [Subject v1.7](https://github.com/AMkuro/pdf/blob/milestone3/Call_Me_Maybe/Call-Me-Maybe.en.subject.txt)
and [confirmed contract #24](https://github.com/AMkuro/Call_Me_Maybe/issues/24).

## Global constraints and decisions

- Work on `feat/a05-common-cli`; baseline is clean and 8 existing tests pass.
- Do not change the SDK, input fixtures, issues, or remote repository.
- Keep default paths and `--functions_definition`, `--input`, `--output`.
  Accept `-output` too, as printed in Subject IV.3.2.
- No actual generation algorithm, Decoder base class, or production fake.
  The default callable raises a clear `NotImplementedError`.
- Flat Subject definitions: all listed parameters required, exact keys, strict
  JSON types. Support number, integer, string, boolean, null, array, object;
  nested schema keywords are rejected rather than silently ignored.
- Use strict Pydantic models and `create_model` with aliases for arbitrary
  argument names; avoid implicit coercion and bool-as-number acceptance.
- Initialize output to `[]` at run start; reject output/input path collisions
  first. Validate each prompt just before generation to preserve earlier
  successes if a later record is invalid. Parse both files before generation.
- Save the complete array using a temporary sibling plus `os.replace`;
  failed writes leave the last published array and clean temporary files.
  No resume, interprocess locking, or power-loss durability guarantee.
- Model ownership, constrained decoding, failure termination reasons, and
  internal metrics belong to future generation implementations. Metadata stays
  outside the Subject output.

## Review focus

- JSON duplicate keys, nonfinite values, and extra prose must fail.
- Integer/float preservation, booleans, and coercible strings need strict tests.
- A malformed second prompt must preserve the first and skip the third.
- Output/input aliases must not destroy inputs; initialization errors must
  prevent generation, and later write errors must preserve published results.
- Ctrl-C during generation or saving must preserve valid output and return 130.

### Task 1: Dynamic input and result validation

**Files:** `src/__init__.py`, `src/validation.py`, `tests/test_validation.py`.
**Interfaces:** `FunctionDefinition`, `Prompt`, `FunctionCall` are Pydantic
models. `load_definitions(path)` returns definitions;
`load_prompts(path)` returns raw records; `validate_result(text, prompt,
definitions)` returns a validated `FunctionCall`.
