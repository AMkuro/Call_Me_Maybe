## 上限と精度の境界

固定 logits では、1・255・256トークンでの終了と、257・1024トークンまで終端が出ない場合を
各3回検証した。上限ちょうどの完了は成功し、超過は理由付きの PromptError となる。

実モデルの長い値は、OMP_NUM_THREADS=8 の3プロセスを並列実行した。時間の評価には使わない。

| ケース | 各実行の値トークン数 | 3回の結果 |
| --- | ---: | --- |
| 32文字 | 22 | 完了したが、末尾空白の欠落で誤答 |
| 128文字 | 73 | 完了したが、余分な引用符などで誤答 |
| 512文字 | 256 | 全回、上限で理由付きの PromptError |
| 17桁の小数 | 20 | 全回、float 正規化後は一致、厳密な数値は不一致 |

2048文字の3実行は計算負荷が大きく、512文字で同じ上限到達を確認済みだったため中止した。
これは製品の PromptError と区別し、未完了の測定として記録した。
当初の多数エスケープ・100桁・400桁の実モデル測定は未実施。
入力 fixture の全9ケースを3回完走した、という主張はしない。

上限を小さくすれば意味の誤りが解決するとは判断できないため、256は引き続き暫定とする。
この表はADR-0017以前の測定で、当時は長い数をfloatへ丸めていた。
現在は値を保持できない小数をエラーにするため、同じ丸めを成功とは扱わない。
測定ツールは Decimal と出力値の表記から厳密な一致を別に判定し、丸めを正答に数えない。
